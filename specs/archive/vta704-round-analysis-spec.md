# VTA-704 — Evidence-grounded round analysis

## Product vision

Help coaches compare how teams play recurring VALORANT scenarios across multiple VODs, find repeated tendencies, and learn from evidence without turning one round into a strategy claim. Eventually the analyzer will answer questions such as how an identified team opens a map/side, how it reacts to early contact, and which supported utility/movement events precede a site commitment. These capabilities depend on reliable upstream round events, player/map identity, and enough independently reviewed rounds. They are a product direction, not claims delivered by this initial slice.

## Initial slice

Add an explicit, offline-first `valoscribe round-analysis` command over a typed evidence bundle. It accepts real upstream HUD `event_log.jsonl` event records when supplied, preserving original event fields, exact round identifiers, timestamps, and their declared clock domain; and it accepts a clearly labeled anonymous diagnostic summary only as availability/limitations metadata. It must not convert anonymous minimap samples into tactical movement, player identity, formation, side, or strategy evidence, nor synthesize an aggregate round from them. Missing HUD source yields an honest report that useful round-level tactical evidence is unavailable.

The output has deterministic observations, optional model-selected observations, typed hypotheses, typed coaching recommendations, and evidence availability as separate concepts. Observations are rendered from locally generated facts and selected by the model only by stable fact ID; safe event details are extracted with a per-event allowlist and source text is rendered locally, never copied from model prose. The structured model response has required selected fact IDs plus bounded lists of hypotheses and recommendations. Every hypothetical statement cites one to four known selected fact IDs; IDs resolve locally to exact JSONL source line, source event, and source timestamp/clock. Model confidence is bounded and explicitly uncalibrated. Claims are visibly hypothetical/suggested and never rendered as observations. Citation membership does not prove semantic support or causality. Samples, distinct rounds, and per-source provenance/coverage are reported; absence and unknowns remain explicit. One round is not evidence of an anti-strat habit.

## Contracts and boundaries

- Evidence bundle and output use strict, versioned Pydantic contracts (`extra=forbid`); all records retain `match_id`, `map_id`, `round_id`, source ID, source timestamp, and clock-domain marker when known. Do not fabricate conversions between match/VOD PTS, game clock, frame number, or wall clock.
- Validate event JSONL line-by-line, finite/nonnegative time, and every explicit match/map/round identifier and clock-domain field, including off-target rows (off-target round IDs must be well-formed; their values are ignored after validation). Reject any explicit clock mismatch; matching-round records must be inside timestamp bounds accompanied by a source review reference. Legacy events without a round number are included only inside the declared reviewed interval. Retain event data as untrusted evidence, not prompt instructions; only whitelisted event fields enter prompts, player names are omitted, and unsafe label values are redacted.
- HUD facts preserve top-level upstream confidence and validated EvidenceRef provenance in typed JSON metadata and Markdown for kill and non-kill events alike. Values are labeled source-reported and uncalibrated; missing or unsupported fields have explicit availability states. Original EvidenceRef notes remain local to the output artifact and never enter model prompts.
- Prompt injection and free-form input: no raw event payload, player name, EvidenceRef note, or arbitrary evidence prose reaches a provider. The bounded provider allowlist contains locally generated fact IDs/text/timestamps, validated numeric source confidence/availability, and bounded evidence source enums/timestamps/confidences. These values are evidence metadata, not instructions. No video/image/upload data is sent; secrets never enter artifacts/logs.
- Disabled is the default and yields the useful deterministic evidence/availability report without constructing a provider or reading credentials. Enabled mode uses existing configured OpenAI-compatible Chat Completions JSON-schema provider, configured model (never hardcoded), and injectable provider transport for tests. The provider schema requires every top-level and nested field, sets `additionalProperties: false` on every object, and uses no defaulted response fields.
- Bound the HUD input log to 20 MB and a selected round to 1,000 source events. Bound optional provider input to 100 fact IDs and 16 KiB of serialized evidence; exceeding either budget skips model selection and keeps deterministic output. Use existing timeout/retry settings. Refusal, incomplete/truncated response, provider failure, schema error, unknown/duplicate IDs, unsupported references, invalid citations, and malformed bundles fail closed to deterministic observations with all model hypotheses/recommendations discarded, or a CLI input error; no invalid model narrative is retained. If `finish_reason` is present, only `stop` is accepted; explicit `length`, `content_filter`, `tool_calls`, unknown values, and null fail closed. Legacy envelopes omitting `finish_reason` remain accepted. Never overwrite outputs; clean up partial output on write failure.

## Acceptance criteria

1. `round-analysis` validates evidence bundle and upstream JSONL scope/bounds and preserves exact identifiers, source timestamps, and clock domain; invalid/mismatched/out-of-bounds events fail with nonzero exit.
2. Missing HUD events and anonymous-only evidence produce a useful deterministic report with explicit unknown/unavailable round tactics and diagnostic limitations; no tactical aggregate is fabricated.
3. Deterministic observations are generated from source facts locally. Enabled model output can select known facts by IDs only; unsupported observations are impossible to render. Hypotheses/recommendations, if used, are visibly hypothetical and reference known source evidence/timestamps; no claim of semantic verification is made.
4. Report separates observations, tentative hypotheses, and suggested coaching practices; resolves citation evidence IDs and source timestamps locally; describes uncalibrated model confidence, diagnostic JSON/Markdown counts, sample provenance, and unknown/missing evidence; does not claim anti-strat tendencies from a single round.
5. Default-off makes no provider/network call and needs no API key. Injected fake provider proves enabled request shape/orchestration without network. No VOD uploads or secret logging/artifact output.
6. Failures include refusal, truncation/incomplete response, malformed/extra response fields, provider exceptions, unknown IDs, duplicate IDs, empty/foreign evidence, invalid timestamps, clock/scope mismatch, and pre-existing output paths.
7. Markdown and JSON outputs are deterministic, non-overwriting, and cleaned up as a pair on partial write failure. Existing deterministic fact API and report behavior remain backward compatible.

## Explicit limitations

The anonymous VTA-404 artifact is not a tactical round aggregate; no accepted live HUD fixture/round aggregate may be available during implementation. Synthetic fixtures establish software behavior only. Citation membership is not semantic entailment. Genuine multi-round HUD evidence, field-specific provenance, and live-provider/real-VOD acceptance remain pending.
