# Smoke candidate extraction

> **Local/future-checkpoint note:** VTA smoke code, scripts, configs, and tests cited here are not included in a docs-only published checkout until a dependency-complete code checkpoint is included. Commands are local/future recipes, not runnable from docs alone; see [`../architecture/publish-boundary.md`](../architecture/publish-boundary.md).

`detect_smoke_candidates` extracts raw circular, HSV-configured color components from an already registered BGR minimap. It emits both individual `SmokeCandidate` records and a `SmokeFrameObservation`; it does not infer an agent from appearance. Candidate attribution remains `None` until independent evidence supplies a supported agent.

Detection is disabled when map-specific `smoke_detection` configuration is absent. No production HSV/area/radius/circularity values are supplied here: calibrate and validate them against reviewed labeled frames before deployment. The caller must provide a registration-approved image and a validity mask for observable pixels. Invalid, hidden, unconfigured or masked input cannot confirm a clear frame. A frame with no candidates is not proof of smoke disappearance; only explicitly verified `active_region_clear` observations may be supplied to `track_smokes` for disappearance confirmation.

The returned overlay marks detected circles for debugging. Synthetic tests exercise expected behavior only; precision, recall, timing error, and real-match performance remain pending a reviewed labeled fixture set.

`track_anonymous_smokes` is an additive generic-geometry path for candidates whose `agent_type` is `None`. It uses scoped, timestamped region observations for disappearance only when the region is explicitly clear, fully observable, live, and covers the entire tracked smoke disc. This generic lifecycle is not evidence of an agent identity and does not count as supported-agent acceptance. The existing `track_smokes` API continues to reject anonymous and unsupported-agent candidates by default; supported-agent acceptance and its metrics remain pending reviewed, canonical-coordinate fixtures.

## Offline lifecycle evaluation (VTA-502)

`valoscribe.analytics.smoke_evaluation.evaluate_smokes` compares predicted `SmokeEvent` values with human-reviewed `ReviewedSmokeLabel` intervals. Supply explicit finite, non-negative `spatial_tolerance` in normalized map coordinates and `temporal_tolerance_s` in VOD seconds; these are evaluation inputs, not detector defaults or production thresholds. Candidates must share match, map, and round, and satisfy both center-distance and appearance-time tolerances. Matching is one-to-one; an endpoint with tied nearest candidates is quarantined, removing every incident match edge, independent of input ordering. Duplicate prediction or label IDs within a match/map/round scope are rejected before matching; IDs may be reused in another scope. Overlapping smoke events remain separate event labels. Precision is unavailable when there are no predictions; recall is unavailable with no reviewed labels. Appearance/disappearance mean and median absolute errors use matched records; disappearance errors use only pairs where both reviewed and predicted disappearance times are known. Null disappearance is explicitly undetermined, never inferred as truth.

This is the generic geometry-and-timing report, not supported-agent acceptance. The separate `evaluate_supported_smokes` entry point emits a `SupportedSmokeEvaluation` scoped to an explicitly supplied supported-agent set. `SupportedReviewedSmokeLabel` requires independently sourced `EvidenceRef` attribution with matching match/map/round scope, finite positive confidence, and a frame path or note; inferred attribution is rejected. Evidence records are revalidated at evaluation entry to catch nested-list mutation. `SupportedSmokeEvaluation` requires explicit `scope: "supported_agents"`; supported-agent names are normalized and UNKNOWN/duplicates are rejected. UNKNOWN/anonymous and unsupported-agent predictions and labels are excluded, with each cohort counted separately. Generic labels lacking attribution evidence are excluded from the supported denominator. Eligible labels and predictions match only when their known agents agree. No production-acceptance flag is set by either evaluator. No real canonical-coordinate label fixture is available, so supported-agent precision/recall and production acceptance remain pending independently reviewed real fixtures; synthetic tests verify contract behavior only.

Future user-provided reviewed label JSON must be a list of persisted `ReviewedSmokeLabel` objects with `schema_version: "1.0"`, non-empty `label_id`, `match_id`, `map_id`, `round_id`, normalized `center: {"x": ..., "y": ...}`, `appeared_at_s`, and `disappeared_at_s` either a reviewed VOD timestamp or `null` when not determined. Labels must be reviewed against the source VOD; do not populate from detector output or guessed timings. Include only authorized user-provided VOD/labels and retain their provenance separately. No real fixture, labels, scores, or deployment calibration are included in this change.

### VTA-502 source-space smoke evidence (not a canonical label)

`tests/fixtures/smoke_source_observation_vta502.json` is a versioned, metadata-only record of source-crop observations. It records the local VOD filename from `tests/fixtures/minimap_calibration_vod_manifest.json`, the source crop `(x=70, y=50, width=360, height=400)`, nominal 60 fps frame references and SHA-256 hashes of decoded BGR crops. It contains no VOD pixels. The independent raw-frame review supports visual appearance only: a teal-rimmed dark circle is visible at 2488–2489.5s, while a faint gray circular footprint appears at 2489.75s and remains visible in the 2490s and 2505s review samples. Whether these appearances are the same feature is unresolved; smoke identity is unresolved, plausibility is moderate, and player association is `UNKNOWN`. Independently supported ability/agent-type evidence is distinct from associating the utility with a specific player; player association is outside this VTA-502 evidence and reserved for VTA-503 fusion. The approximate later footprint center `(251,155)` source-crop pixels has exploratory uncertainty ±3 px (not ±2); it is not a smoke label or canonical coordinate. The separate red marker near `(90,194)` is not this reviewed footprint.

The manifest's older sample kinds and timing bounds—including asserted absence at 2487s, presence from 2489.75s through 2505.133333s, and absence at 2505.366667s—are retained as historical reviewer assertions, not currently verified smoke presence/onset/disappearance evidence. Do not use them as a confirmed appearance bracket, a continuous interval, or an accepted timing result. Establishing smoke ground truth requires independent identity reconciliation between the earlier teal circle and later gray footprint, evidence supporting continuity (or explicitly separating them), and independently supported ability/agent-type evidence. A specific player association may remain `UNKNOWN` and is reserved for VTA-503; roster-only type inference is not the supported-evidence gate. Until those prerequisites are met, candidate output remains exploratory and production acceptance is pending.

A separate bounded raw-frame observer review and its provenance are documented in [VTA-502 deployment evidence review](smoke-deployment-review-vta502.md). It does not reconcile or replace the unresolved historical observations above, and it is not issue completion.

This does not complete full HUD calibration or map geometry validation: both remain pending. This observation deliberately does not populate `ReviewedSmokeLabel`; a canonical label still requires frame-specific registration evidence and independently supported center uncertainty in canonical-map coordinates. Smoke evaluation, precision/recall, and canonical-coordinate acceptance remain blocked until those prerequisites are independently reviewed.
